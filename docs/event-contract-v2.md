# Event v2：操作与执行的观测契约

设计草案，尚未实现。语义依据是 [pVisor 核心：操作、组合与改写](pvisor-algebra.md)。
本文只定义 Event 的公共信息、关联、采集与提交要求；操作、规则和后端的行为由核心文档
及对应原语契约定义。下面的类型是语义草图，不是当前运行时 API。

## 1. Event 记录什么

**Event 是一次请求、改写、执行或外部状态变化的不可变观测记录。**
它连接核心文档中的两个观察面：

| 观察面 | 记录内容 | 文件读取示例 |
|---|---|---|
| Agent 接口 | 请求、策略改写、最终交付的 Outcome | 读取哪个文件、是否替换、返回哪些字节或错误 |
| pVisor 内部执行 | 后端实际动作、资源变化、收尾与审计状态 | 访问远端、暂停 VM、准备响应、释放暂停 |

后端内部步骤按实际观察点记录，不必转换成 Agent 操作或 Rule。内部记录的披露由权限决定，
不会因为它与 Agent 的请求有关就自动向 Agent 开放。VM 意外退出等观察可以没有原请求。

Event 描述已经观察到的事实，不执行操作，也不授予权限。策略允许不表示操作已经发生；
记录“返回模拟内容”不表示真实文件被读取。取消、恢复与补偿产生后续事实，保留此前历史。

## 2. 公共信息与领域载荷

公共层只保存跨领域关联所需的信息。生产者使用类型化 payload，存储时按事件类型编码：

```rust
struct Event<T> {
    schema_version: u16,
    id: EventId,
    ty: EventType,                     // domain + name + payload version
    source: EventSource,               // component + producer instance
    observed_at_unix_ms: u64,
    scope: ScopePath,
    context_ref: ContextRef,           // 核心 Context 的固定版本
    operation_id: Option<OperationId>,
    granularity: Granularity,
    severity: Severity,
    links: Vec<EventLink>,
    data: T,
    omissions: Vec<FieldOmission>,     // 未采集、脱敏、截断或不可用的字段
}
```

| 信息 | 契约 |
|---|---|
| `id` | 标识一条事实，重试、复制和引用时保持不变 |
| `ty` | 固定领域、事件名称与载荷版本；名称表达发生了什么 |
| `source` | 标识实际记录组件和生产者实例，由可信执行端绑定 |
| `observed_at_unix_ms` | 该生产者的观察时间，不建立跨进程或 Guest/Host 的因果顺序 |
| `scope` | 执行归属路径，如 Run / Attempt；不代表权限或依赖图 |
| `context_ref` | 指向当时的资源绑定、策略与记录配置，不用当前配置解释历史 |
| `operation_id` | 关联同一次操作的多条记录；外部状态观察可为空 |
| `granularity` / `severity` | 分别表示记录粒度与严重程度，见下节 |
| `links` | 显式引用触发原因、父请求或推导证据 |
| `data` / `omissions` | 保存领域事实与实际省略说明，区分空值和未采集 |

ID、名称和引用经验证后构造；生产端确定身份并按采集策略生成事件后，内容不可修改。
重试提交复用同一事件。实现必须限制载荷大小、路径深度和引用数量，大内容通过受控引用保存。
引用的上下文与内容应在约定保留范围内可解析；缺失时报告缺口。

文件路径、HTTP 状态、VM 状态、规则版本、后端实例和操作契约版本由相关 payload 定义。
公共层不维护包含所有领域的巨型枚举。能够读取公共信封时，可以保留和转发未知载荷；
未知载荷不能被当成已理解的状态转移，未知公共格式版本须明确拒绝。

每种事件还要定义其观察依据：直接观察、接收外部报告，或从已有证据推导。
接收端保留报告者身份，不能将客户端声明升级成宿主确认；派生结论保留规则与证据引用。
这些含义写入事件类型契约和相应 payload，不再设置一个全局 `evidence_basis` 枚举。
有可靠发生时间或持续时间时，也由具体类型说明其来源与时钟。

## 3. 领域与粒度

领域描述事实内容，例如 filesystem、http、network、vm、policy、runtime、llm、audit。
组件是来源，不是领域：OverlayNet 可以产生 network 和 policy 事件。
HTTP 传输结果与 LLM 语义结果分别定义、显式关联，不能由 HTTP 200 推断模型调用成功。

| granularity | 用途 | 例子 |
|---|---|---|
| milestone | 关键决定或状态边界 | 策略拒绝、apply 提交、VM 状态变化 |
| operation | 一次操作的请求、结果或交付 | 文件读取、HTTP 请求 |
| detail | 解释内部执行的细节 | copy-up、传输分块 |

每种事件类型固定粒度；不能为了避开采集要求将其降为 detail。
severity 使用 trace / debug / info / warn / error。正常的策略拒绝可以是 info，
是否必须记录由操作契约与采集要求决定。

粒度不区分 Agent 接口与内部执行，也不代表披露权限。高层摘要需要显式推导；
筛掉 detail 只是减少记录，不自动得到正确的高层结论。具体事件词汇随原语契约逐项定义。

## 4. 归属与关联

Scope 使用稳定的归属路径。子 scope 继承父路径，生命周期内不换父级；重试执行使用新的
Attempt。共享 VM 可以属于 Runtime / VM，由使用它的操作引用资源身份，不强行挂到某个 Run。
`local` 可以改变 `context_ref` 而不改变 scope；后续计算恢复父 Context。
宿主观察使用真实的 runtime Context，不伪造一个 Agent 请求上下文。

一次操作的各阶段共用 `operation_id`；改写产生的子操作和新的操作尝试使用新 ID。
同一操作的重复记录不等于执行了多次，也不能仅凭内容相同合并两次独立调用。
后端内部动作可以关联原操作；需要独立跟踪其生命周期时才分配子操作身份。

| 关联 | 含义 |
|---|---|
| `caused_by` | 某个已发生事实触发或允许了本次动作 |
| `delegated_from` | 子操作由哪个原请求或改写产生；内部子操作仍按其观察点标明身份 |
| `derived_from` | 结论使用哪些记录作为证据，不宣称它们触发了执行 |

关联保存在后产生的事件中，引用先前事实。禁止自引用、重复边和因果环。
跨生产者记录可乱序到达，暂未解析的引用保留为缺口；同 scope、时间相近、日志相邻都不
自动构成因果。跨日志只能保留已知偏序，不补造全局执行顺序。

## 5. 请求、改写与结果

下面是一条被策略替换为远程读取的轨迹；各行是观察点，不要求统一为一个全局 phase 枚举：

| 记录 | 操作身份 | 必须能解释的内容 |
|---|---|---|
| 收到读取请求 | A | 原文件、偏移、长度和 Context |
| 选择替代计算 | A | 规则及版本、改写阶段、替代资源与后续关联 |
| 发起远程读取 | B，关联 A 的改写 | 实际绑定、后端与契约版本、授权依据 |
| 远程读取结果 | B | Outcome、已知效果与实际返回内容或其省略说明 |
| 向调用者交付 | A | 交付的 Outcome、结果来源，以及 B 的结果证据 |

匹配规则时保留原请求与改写证据，再执行替代表达式。即使替代为 `pure (Right bytes)`，
原请求与规则记录也不能随 Call 消失。结果相关的子操作在实际产生时补记，不预先虚构
未执行的分支，也不序列化任意 continuation。

应答 payload 使用 `result_origin` 区分 driver、policy、replay，并保留来源引用。
策略直接应答或替换计算产生的父应答归于 policy，实际子操作结果归于 driver。
后端按同一操作契约完成内部流程时，接口结果仍归于 driver，不因为内部有多个步骤就
成为策略改写。优化记录其规则、原有依赖与实际次序，不把日志排回未发生的顺序。

各结果分支沿用核心文档的 Outcome：成功、Failed（含部分效果）、Denied、Unsupported、
Unknown。准入拒绝、改写拒绝和交付拒绝都留下相应结果记录；后续拒绝不抹去已发生的子操作。
直接 mock/deny 不产生原目标的执行成功事件。取消另记实际取消点及已知效果，不能把调用者
停止等待等同于远端未执行；后续确认以新事件关联此前的 Unknown。

操作结果、收尾结果和审计提交结果分别记录。VM 后端的暂停确认、响应准备和释放由其
契约定义观察点；释放本次暂停原因不等于确认 VM 已运行。具体流程沿用核心文档 §4.1，
Event 不再定义另一套 VM 状态机。

## 6. 采集、披露与重放

采集配置只需说明三件事：记录哪些事件、保留哪些字段、哪些提交是执行前提。
可以按粒度增加诊断细节；必需事件不能被严重程度过滤或采样丢弃。字段权限独立检查，
增加事件范围不会自动增加正文或内部执行信息的披露权限。

字段保留规则由事件类型定义，不统一规定 metadata / semantic / content 三套载荷。
在任何持久化路径之前处理敏感内容，并记录未采集、脱敏、截断或不可用的原因。
导出删减后的视图仍可引用原事件，但不得冒充原事件重新提交；新的统计结论使用新 ID。
关联证据的补读同样受权限约束，删减后的视图说明缺失的引用。

采集窗口说明观察入口、事件集合、配置版本及已知丢失情况，正常结束时记录闭合状态。
没有关闭证据或存在未确认丢失时，不声称窗口完整。覆盖范围、引用齐备程度、内容省略与
存储校验分别说明；代理路径的完整记录不能证明所有网络活动都被捕获。

重放遵循核心文档 §7：固定初始状态、配置与契约版本，使用必要输入、内容和交付顺序，
去重后在模型中重建声明的状态。多个观察点和派生摘要不能重复应用同一次状态变化。
缺失内容或证据时报缺口；哈希不能代替内容，Unknown 保留当时的未知判断。
必须说明恢复到哪个前缀或闭合窗口；合法前缀不等于完整运行。重放不再次执行真实副作用，
修改策略或调度属于分叉实验。

## 7. 提交与存储

Event 身份与存储位置分开。journal 为已提交记录分配位置，位置只表示该日志的提交顺序。
不同日志的位置不作大小比较，也不代表动作发生顺序。日志正常重开保留身份；替换为新日志
时使用新身份。事件复制到其他日志后保留原事件身份。

提交接口的最小约定是：

| 情况 | 保证 |
|---|---|
| 接收入队 | 只表示等待处理，不代表持久化 |
| 提交成功 | 回执包含事件 ID、日志位置和明确的持久性保证 |
| 确定未提交 | 调用方可用原事件重试 |
| 提交结果未知 | 保留原 ID，查询或重试；不能按“未发生”处理 |
| 同一 journal 内同 ID 重试 | 同内容返回原回执，不同内容拒绝；重开日志后仍有效 |

取消等待不撤销已经交给 writer 的提交。位置分配和写入由 writer 管理，不能依赖调用方
Future 是否存活。无法判定是否接收或提交时按未知处理。事件去重不承诺业务效果只执行一次。

要求事前审计的动作，只有相应记录达到约定持久性后才可执行；内存接收不能满足这一要求。
外部效果与日志不是同一事务。效果已发生而记录失败时，保留执行结果并报告审计缺口，
不伪装成回滚。日志不可写时经运行结果或管理接口暴露故障，不保证能往故障日志追加说明。
可选记录丢失也要暴露已知丢失或未知状态。

首版沿用本地 JSONL。同步确认、尾部恢复、幂等状态和稳定位置由 writer 契约与故障测试
保证；已确认记录不可静默改写或丢弃，中间损坏必须报告。持久性声明须列出适用的同步与
故障假设，日志完整性也不等于防篡改。具体队列、索引与订阅 API 在实现时确定。

## 8. 契约测试与接入

每种事件随所属原语或后端定义：产生条件、payload 与版本、粒度、观察依据、操作归属、
允许的关联、字段省略规则和测试。公共层只验证通用约束，领域层验证具体事实含义。

| 契约 | 必测性质 |
|---|---|
| 公共信封 | 格式版本、类型与字段验证；载荷大小、路径深度和引用数量边界 |
| 身份与 Context | 重试身份稳定；内容冲突拒绝；绑定旧版本；客户端不能伪造宿主来源 |
| 归属与关联 | 子 scope 继承；共享资源不改归属；子操作、乱序引用和因果缺口可辨 |
| 改写与交付 | mock 无目标执行；所有拒绝分支有结果；原请求、规则、子操作和交付可追溯 |
| 后端与失败 | 部分效果、Unknown、取消、收尾失败与审计失败分别保留 |
| 采集与披露 | 必需事件不被过滤；敏感字段不进入持久路径；缺失证据不虚报完整 |
| 提交与恢复 | 并发位置唯一；在接收、写入、同步、回复处取消或崩溃；重开后重试不重复 |
| 重放 | 内容缺失、身份冲突和顺序偏离被识别；尾部缺失不冒充完整运行；模拟重放无真实 I/O |

先在文件操作闭环中确定观察点与事件类型，再复用到 HTTP、网络和 VM。
无 I/O 的公共类型与验证留在 `persisting-control::events`，领域 payload 属于各组件，
writer 留在运行时；这次不新增 EventBus、插件机制或 crate。

接入时保留 v1 reader，旧文件不混写 v2。旧记录的 ID/seq 保留为来源信息，导入使用稳定
身份映射；缺失的上下文、来源与关联明确未知，不补造执行证据。旧日志不能直接取得
新协议的持久性或完整性保证。迁移与字段编码随首个闭环确定，不在本稿预设完整重写顺序。

{% if zh %}规模化的三根支柱{% else %}Three pillars for scale{% endif %}

{% if zh %}边界、证据、兜底{% else %}Boundaries, evidence, and a fallback{% endif %}

{% if zh %}自主能扩到多大，取决于每一份信任有多可靠。pVisor 用可强制的边界建立信任，用可核对的记录证明信任，并在信任不足时提供审查兜底。{% else %}How far autonomy scales depends on how reliable each unit of trust is. pVisor establishes trust with enforceable boundaries, proves it with checkable records, and falls back to review when trust is short.{% endif %}

{% if zh %}边界{% else %}Boundaries{% endif %}

{% if zh %}选择执行器与能力要求，落实实际可强制的控制，并暴露不支持的缺口与降级。{% else %}Choose the executor and capability requirements. Install the controls that can be enforced, and surface the gaps and degradations that cannot.{% endif %}

{% if zh %}证据{% else %}Evidence{% endif %}

{% if zh %}每次 Run 产出可核对的记录：实际安装的控制、观察到的结果与警告。声明不当作证据。{% else %}Every Run produces a checkable record: the controls actually installed, the observed results, and the warnings. A declaration is not evidence.{% endif %}

{% if zh %}兜底{% else %}Fallback{% endif %}

{% if zh %}信任不足时，工作区先暂存、审查再应用；随信任上升，转向事后审计与更少的介入。{% else %}When trust is short, stage the workspace and review before applying. As trust grows, shift to post-hoc audit and less intervention.{% endif %}

{% if zh %}计划与实际控制{% else %}Plan versus installed control{% endif %}

{% if zh %}准入计划说明执行器准备提供什么，最高只到 Planned。实际强制力只来自执行器收尾返回的观察集，安全摘要从它派生。{% else %}The admission plan states what an executor intends to provide, and never exceeds Planned. Actual enforcement comes only from the observations the executor returns at teardown, and the safety summary derives from them.{% endif %}

{% if zh %}明确记录的范围{% else %}Know what the record covers{% endif %}

{% if zh %}apply 与 drop 管理暂存文件，不能撤销外部 API 调用。观察只覆盖到达控制点的操作，null 表示未观测；捕获按需启用。{% else %}Apply and drop govern staged files; they cannot undo external API calls. Observations cover only operations that reach a control point, and null means unobserved. Capture is optional.{% endif %}

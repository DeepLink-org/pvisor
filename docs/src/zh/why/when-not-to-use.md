# 什么时候不需要 pVisor

判断标准只有一条：**你本来就会全程盯着这次执行。**

- **就在眼前跑、全程盯着**：审批和纠错都发生在当下，后置审查没有意义。
- **改动用 git 就能轻松回退**：diff 小、随时 `git checkout` 就干净，暂存和选择性合入省不了多少事。
- **主要副作用在外部**：远程 API、数据库写入、已发出的消息，暂存管不了，回滚得靠别的手段。
- **需要敌对的强隔离**：面对不可信多租户，要的是 VM 级隔离基座，pVisor 只是其中一个执行器选项。

pVisor 的适用面正相反：你**想放手让 Agent 跑，又不打算全程盯着**。这时目标不是挡住每一个动作，而是把监督从过程挪到结果——跑完审查一次改动和证据，只合入想要的。

与其他方案的取舍见[对比](comparisons.md)。

# 信任阶梯与规模轴

pVisor 的路线由两条轴描述：**人怎么介入**（信任轴）决定能放手多少，**由什么承载**（规模轴）决定放手之后能跑多少。

| 级别 | 人怎么介入（信任轴） | 承载（规模轴） | 状态 |
| --- | --- | --- | --- |
| L0 | 逐条批准命令 | 单个交互会话 | Agent 自带 |
| L1 | 放手执行，事后审查每个改动 | 本机，逐个 Job | **pVisor 今天** |
| L2 | 由策略和证据决定哪些改动免审，人只抽查 | 本机多个 Job；一条流水线 | 下一步 |
| L3 | 事后审计，人只处理例外 | 集群化执行：跨节点调度、集中证据 | 方向 |

每一级都建立在同样的三种性质（有界、可逆、可查）上，区别在于这些性质有多可靠、能被机器消费到什么程度。

## L1：放手执行，事后审查（今天）

**已具备**：暂存与选择性 apply、冲突时拒绝覆盖、敏感路径默认保护、host/container/VM 三种执行器、区分计划与实际控制的证据模型、可选的模型流量捕获、逻辑检查点与分叉。

**人的工作**：每次运行结束后读一遍审查结果，决定合入哪些路径。

## L2：由策略和证据决定免审（下一步）

**进入条件**：

- 证据足够可靠，可以由机器判定"这次改动落在允许范围内"，例如只改了 `src/`、没有被拒绝的访问、网络只到达授权目标；
- 单机上同时运行多个 Job，各自隔离、各自留证据；
- 批量审查：一次查看多个 Job 的结果，只对超出策略的部分人工介入。

**主要缺口**：基于证据的自动免审规则；多 Job 并发的资源与密度数据（见[并发密度（规划中）](../benchmarks/density.md)）；批量审查界面；审查输出的降噪。

## L3：事后审计，集群化执行（方向）

**进入条件**：证据可以集中保存和查询，策略可以统一下发，执行可以跨节点放置。

**pVisor 与调度器的边界**：pVisor 定义每一次执行的语义（暂存、证据、分叉、回放），节点分配交给 Kubernetes、Ray、Slurm 等现有调度器。pVisor 作为每个节点上的执行层，加上一个汇总证据的地方，而不是另一个调度器。

| 已有的基础 | 还缺的部分 |
| --- | --- |
| 执行器抽象：host、容器、VM | 远程执行器或节点代理 |
| Operation 中已有 Placement 字段 | 跨节点的放置决策，以及与调度器的集成 |
| Run Bundle 与证据不依赖宿主机，可以迁移 | 集中的证据与日志存储、查询和审计 |
| 策略在准入阶段生效 | 策略下发与多租户隔离 |
| Gateway 捕获、回放与分叉 | 多租户 Gateway；在集群范围对 rollout 分叉和回放 |

研究方向的细节见[集群化执行（规划中）](../design/research/cluster-execution.md)。

## 用什么衡量进展

这条路线的指标是**每单位 Agent 工作所需的人工监督成本**：从 L1 到 L3，人工介入的次数和时间应当持续下降，而任务成功率不下降。度量方法见[监督成本（规划中）](../benchmarks/supervision-cost.md)。

# PolicyVisor 是什么

**PolicyVisor（pVisor）**为现有 Agent CLI、脚本和自动化命令提供**策略约束下的可审查执行**。你继续使用原来的工具，pVisor 负责能力准入、运行时控制、可选的文件暂存，以及本地执行记录。

**p 代表 Policy**。一次 Run 将声明的权限、实际安装的控制和可供审查的执行结果关联起来。它们之间的关系见 [PolicyVisor 的设计思路](../concepts/policyvisor.md)。

```bash
pvisor run --stage ../task-stage -- codex
pvisor review last
pvisor apply last --all
```

!!! tip "显式启用暂存"

    `--stage` 创建供 review/apply 使用的写时复制工作区。不使用它，宿主机命令可能直接修改项目。

## 你会得到什么

- **能力准入与运行时控制：**根据所选执行器评估权限要求，记录实际控制和降级情况。

- **一次运行的记录：**命令、执行器、结果、警告，以及实际安装的控制机制。
- **可选的暂存工作区：**查看文件改动，分批应用，或丢弃剩余改动。
- **可选的网络策略和 Gateway 捕获：**控制经过中介的流量，记录模型请求与响应。
- **逻辑检查点与派生运行：**保留暂存文件系统状态，开始一段关联的新运行。

## 保证到哪里为止

宿主机、容器和 VM 的边界不同。存在暂存目录，不代表所有宿主路径或网络连接都已隔离。请查看 `pvisor review` 中的警告和能力证据。

`apply` 和 `drop` 管理暂存文件，无法撤销已经发生的外部 API 调用、数据库写入或消息发送。逻辑检查点不保存进程内存。分布式调度和面向恶意租户的多租户隔离不属于当前本地工作流。

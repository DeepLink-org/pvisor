# PolicyVisor 是什么

**PolicyVisor（pVisor）让 Agent 全自动执行，文件改动由你决定去留。**

不少 Agent CLI 已经自带沙箱或审批模式。它们回答的是"能不能挡住"，但没有回答"到底改了什么、哪些该留下、有什么可核对的记录"，也不跨 Agent、跨执行器。pVisor 补上这三件事：让你现有的 Agent CLI、脚本或自动化命令在策略边界内全自动执行，结束后像审 PR 一样，只合入你想留下的改动。

## 为什么是"规模化"

限制 Agent 自主性的不是算力，而是人的监督带宽。今天每一单位 Agent 工作，都要付出差不多同等的人工注意力——事前逐条批准，事后通读排查，或者出了事再收拾。监督成本随执行量线性增长，自主性因此被人的注意力封顶。

要让监督与执行量脱钩，需要每次执行同时具备三种性质：

| 性质 | 含义 | 对你的作用 |
| --- | --- | --- |
| 有界 | 出错的影响范围事先可知 | 不必逐条事前批准 |
| 可逆 | 暂存文件可选择性合入、丢弃或分叉 | 失败成本低，敢于放手 |
| 可查 | 执行留下可核对的证据 | 审查可以抽样，直到交给机器 |

pVisor 就是让 Agent 执行具备这三种性质的执行层。委托的规模因此由策略和证据决定，而不是由人盯着的时间决定。

## 你会得到什么

- **放手**：不用守着批准弹窗。Agent 的文件改动先进暂存区，网络与敏感路径按策略约束。
- **把关**：像审 PR 一样查看改动，选择合入哪些路径，其余一键丢弃。若你期间改了同一个文件，pVisor 拒绝覆盖你的修改。
- **有据**：每次运行留下一份可核对的记录，包括实际生效的限制、被拦下的访问，以及可选的模型请求。

## 为什么不用现成的方案

| 方案 | 能做到 | 缺什么 |
| --- | --- | --- |
| Docker / devcontainer | 隔离环境、依赖可复现 | 改动审查、冲突时拒绝覆盖、按路径选择性合入、实际生效限制的证据都要自己搭 |
| Agent 自带沙箱 | 挡住部分命令 | 逐条或整块放行，不跨 Agent／执行器，无可核对记录 |
| git worktree | 文件层隔离 | 不管网络与凭据，也不产出证据 |
| 云端沙箱（如 E2B） | 远程隔离执行 | 脱离本地工具链与工作区，本地审查链路缺失 |
| Kubernetes / Ray | 调度与编排执行 | 调度的是进程，不是"有界、可逆、可查"的执行语义 |

什么时候不需要 pVisor：如果你只要一个用完即弃、用 `git checkout` 就能扔掉的沙箱，也不需要可核对的证据或选择性合入，Agent 自带沙箱或 Docker 就够了。

## 今天能做到哪一步

今天 pVisor 在本机逐个 Job 运行：让一个 Agent 全自动跑完，事后审查每个改动并选择性合入。这一级已经具备通往更高自主级别的三种性质——由策略和证据决定哪些改动免审、人只抽查，直到事后审计、多个 Agent 并行，最终交给集群化执行。分级与路径见[近期工作](../development/roadmap.md)。

```bash
pvisor run --safe --stage ../task-stage -- codex
pvisor status --review ../task-stage
pvisor apply ../task-stage --all
```

`--safe` 默认保留暂存工作区，`--stage PATH` 可指定位置。

## 保证范围

一次运行的边界以它的能力证据为准；`apply` 和 `drop` 只管理暂存文件，不撤销外部副作用。完整口径见[能力、证据与保证边界](../concepts/capabilities-and-evidence.md)。

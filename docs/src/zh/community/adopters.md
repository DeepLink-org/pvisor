# 使用者与案例

如果你正在考虑采用 pVisor，可以先按任务类型试用：让编码 Agent 自主修改项目，在 CI 中收集候选改动，或者批量生成可评分的 rollout。一次小任务足以验证执行、评审和接受改动是否适合你的工作流。

当前没有在此登记、获得公开授权的组织案例。下面是可复现的试用路径；组织名称、logo 与生产规模需要使用者确认后再发布。

## 从你的工作流开始 {#start}

| 使用场景 | 第一次试什么 | 看什么结果 |
| --- | --- | --- |
| 本地编码 Agent | 一项小修改，暂存后检查 | 文件 diff、测试结果与 apply 选择 |
| CI 自动修复 | 一个离线脚本，再替换为 Agent | 失败记录、Stage 产物与评审交接 |
| 多 Agent 并行 | 两个独立 worktree | 各自结果可定位，合入没有混淆 |
| RL rollout | 单个候选收集与评分 | 输入版本、轨迹、reward 与失败类别对应 |

对应步骤见[CI](../guides/ci.md)、[并行 Agent](../guides/parallel-agents.md)与[rollout](../guides/rl-rollouts.md)。先验证你的任务，再按实际负载测量速度与容量。

## 分享一份有用的案例 {#case}

描述原来的工作流、要解决的问题、pVisor 版本、平台与执行器、Agent 和模型版本、关键命令或配置，以及任务后的评审方式。给出一段能公开的任务输入和结果，说明采用之后实际改变了什么。

性能数字带上任务数量、机器与测量方法；人工体验描述对应到具体操作，例如授权次数、集中看 diff 或处理冲突。失败案例和后来调整的配置同样有价值。

提交前确认组织名、logo、引用和数据得到公开授权。私有代码与凭据可以替换为公开复现；无需上传包含秘密的完整日志。

## 案例记录字段 {#fields}

每条记录保存组织或个人署名、公开授权范围、日期、版本、任务类型、集成方式、规模、指标定义和原始材料链接。尚未授权的案例不列名；实验性试用与生产使用分别说明。

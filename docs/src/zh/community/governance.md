# 治理与维护者

pVisor 目前由一位维护者负责代码合并、发布、semspec 批准和文档定稿。项目尚未设立正式委员会、多维护者投票机制或治理章程。

## 贡献如何进入 {#workflow}

1. 描述用户遇到的问题、预期行为和复现方式；较大的接口与行为变化先用 issue 对齐问题和验收方式。
2. 提交实现、对应文档与验证结果；按[贡献指南](contributing.md)运行相关检查。
3. 维护者核对行为、证据与测试后合并。涉及安全边界的漏洞使用[私密披露流程](../security/disclosure.md)。

代码评审、合并与语义规格批准分别处理：一个 PR 的测试通过不自动批准产品承诺；新增用户可见边界需要对应的规格与人工审核。

## semspec 批准 {#semspec}

贡献者可以起草案例、修复实现并维护 runner 测试。semspec 的 approve/revoke 与真实 `REVIEWED.toml`、`.approved/` 快照只由维护者人工执行；AI 不执行批准，也不弱化现有检查来获得 PASS。具体命令与规则见[测试与 semspec](testing.md)。

## 尚未建立的部分 {#records}

正式的维护者名单、治理章程和行为事件私密报告渠道尚未设立，设立后将在此页公布。在此之前，设计决定以 issue、PR 或 ADR 链接为准，讨论约定见[社区](index.md)。

# 行为准则

讨论实现、报告问题和评审贡献时，请把注意力放在可观察的行为与证据上，让不同经验、背景和表达方式的参与者都能继续合作。

当前尚未正式公布 Contributor Covenant 的采用记录与行为事件私密联络渠道。以下是参与讨论的实用约定；正式政策仍待维护者确认。

## 让讨论更容易推进 {#participation}

- 指出问题时附上版本、平台、复现或具体段落，让对方能采取行动。
- 评审代码时解释影响与可接受的修改，不评价贡献者的能力或身份。
- 出现分歧时先复述双方需要解决的问题，再比较方案和验收结果。
- 对新参与者解释必要上下文；允许提问、修正理解和承认不确定性。

侮辱、骚扰、歧视、威胁、公开他人私人信息以及持续针对个人的攻击会破坏合作。技术分歧应围绕方案展开。

## 遇到不当互动时 {#response}

可以暂停对话，保留相关链接、时间与记录，避免继续扩大冲突。若你已有维护者的私密联络方式，可询问适合的处理入口。公开 issue 可以讨论流程改进，但不要在其中披露受影响者身份、私人消息或事件敏感细节。

项目仍需公布可用的私密行为事件报告渠道、负责处理的人员、回避机制和反馈时间。漏洞报告渠道用于安全漏洞；安全问题按[披露政策](../security/disclosure.md)提交。

## 适用范围 {#adoption}

这些讨论约定适用于项目的 issue、PR、评审与社区交流。技术争论可以保留不同观点，但应让参与者能够继续贡献和获得回应。

正式行为事件处理需要私密渠道与负责人员。目前没有公开的专用联系人；本仓库的安全漏洞渠道继续按安全披露政策使用。

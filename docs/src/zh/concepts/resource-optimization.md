# 镜像与内存优化

并发 Agent 环境通常共享依赖、镜像和部分状态。pVisor 在镜像加载与内存存储层复用相同内容、压缩合适的冷内容，减少环境准备和运行期间的资源开销。

## 优化发生在哪一层 {#resource-layers}

镜像缓存复用不可变文件内容；RAM 基底与内存去重减少重复驻留页；压缩减少可压缩内容的字节数。三者有不同的所有权、恢复方式和适用条件。相同镜像名或文件内容不代表 guest RAM 已共享，具体机制见[共享工作集与按需加载](../design/daemon/shared-working-set.md)。

## 按需加载、共享与压缩 {#resource-mechanisms}

**按需加载**延后读取尚未访问的镜像内容或检查点 RAM，减少启动时必须准备的数据；后续读取可能承担缺页与加载延迟。当前镜像格式与配置见[共享镜像缓存](../reference/shared-image-cache.md)。

**内存共享与去重**减少多个实例中的重复页，同时通过私有写入保持隔离。**内存压缩**减少可压缩内容占用的字节，也能处理独特的冷内容，但需要编码、解码和恢复余量。各路径的平台条件及组合限制见[内存架构与机制](../design/memory-optimization/index.md)。这些机制按支持配置选用，不能假定同时启用。

## 与生命周期管理协同 {#lifecycle-and-cost}

状态复用减少重复内容，生命周期管理决定环境何时运行、何时保留状态并回收驻留资源。暂停与整机卸载的流程见[沙箱生命周期管理](lifecycle.md)，恢复和分支时仍需预算私有修改、元数据与临时缓冲。

评估并发容量时，应同时观察节点总内存、恢复峰值、任务耗时和吞吐。局部压缩比或单实例驻留下降，不能直接换算为可增加的 VM 数；现有证据见[VM 内存基准](../benchmarks/vm-memory/index.md)与[并发密度](../benchmarks/density.md)。

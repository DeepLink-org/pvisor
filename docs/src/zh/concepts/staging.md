# 暂存与 apply 语义

暂存（stage）把 Job 对工作区的改动留在写时复制的上层中；只有显式 `apply` 才会改变目标工作区。这是"可逆"的来源：在 apply 之前，任何改动都可以被选择性合入、整体丢弃或分叉。

本页是暂存语义的权威定义。每条承诺都对应 `tests/semantics/stage-apply.md` 中的一条语义规格，可以用 `just semantics` 复现；操作步骤见[审查并应用改动](../guides/review-apply.md)。

## 承诺

| 承诺 | 含义 | 语义规格 |
| --- | --- | --- |
| apply 前工作区不变 | Job 成功、非零退出或被信号终止后，apply 前工作区的路径、类型、内容、权限位和链接目标都与开始前一致 | S-STAGE-001 |
| Job 读到自己的改动 | Job 内能看到自己的写入、删除和重命名，宿主工作区仍然不变 | S-STAGE-002 |
| 审查清单是净效果 | 清单精确等于文件的净增、删、改；创建后又删除的临时文件不出现 | S-STAGE-003 |
| 全部应用等价于直接运行 | 同一脚本暂存后 `apply --all`，与直接在工作区执行得到相同的完整树 | S-STAGE-004 |
| drop 之后不能 apply | drop 后工作区不变，之后对该 stage 的 apply 被拒绝且没有效果 | S-STAGE-005 |
| 选择性 apply 只影响所选子树 | `apply --path P` 只改变 P 及其后代；两次选择性 apply 覆盖全部改动时，等价于一次 `--all` | S-STAGE-006 |
| 重复 apply 无额外效果 | 对已应用的路径再次 apply 不改变工作区 | S-STAGE-007 |
| 冲突时拒绝，保留外部改动 | 暂存后目标被外部修改、新建或删除，apply 被拒绝，外部状态完整保留 | S-STAGE-008 |
| 冲突时整批无效果 | 所选集合中任一路径冲突，本次 apply 不改变集合中任何路径 | S-STAGE-009 |
| 无关的外部改动不阻止 apply | Agent 没有触碰的路径上的外部改动不影响 apply，并全部保留 | S-STAGE-010 |
| 删除目录不吞掉外部新增 | Agent 删除了目录、外部又向其中新增文件时，apply 被拒绝 | S-STAGE-011 |
| apply 不越出工作区 | 目录在暂存后被替换成指向外部的链接时，apply 被拒绝，内外两棵树都不变 | S-STAGE-012 |
| 调用返回值与效果一致 | 创建链接的调用成功则链接存在，失败则不存在 | S-STAGE-013（macOS 上为已知缺口，见下） |
| 保留可执行位和链接目标 | 可执行位和符号链接目标原样落地，链接不会被解引用 | S-STAGE-014 |

这些规格目前是未经人工批准的草稿：通过测试说明实现满足脚本，不等于语义已经审核。审核规则见[测试与 semspec](../community/testing.md)。

## 已知缺口

- **S-STAGE-013 在 macOS 上标为 XFAIL**：macFUSE 上创建符号链接可能返回 EPERM，但链接已经实际创建。见[已知限制](../security/known-limitations.md)。
- **重命名显示为删除加新增**：审查清单不单独表示重命名。
- **多文件 apply 不是对外部编辑器的原子操作**：冲突检查在写入前进行，apply 期间应停止其他写入者。中断后，`apply-ledger.json` 让已准备的批次向前恢复。

## 不可逆的部分 {#不可逆的部分}

暂存只覆盖工作区文件。下面这些不经过暂存，`apply` 和 `drop` 都无法撤销：

- 远程 API 调用、数据库写入、已发出的消息等外部副作用；
- 显式 `--mount SOURCE:write` 共享的宿主路径；
- 已经 apply 的批次（drop 不会撤销它们）。

HOME、VM 根目录等其他写入的去向见 [暂存与存储](../reference/cli.md#暂存与存储)。

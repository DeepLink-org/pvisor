# 文件级监管与隔离 {#apply}

<span id="staging-and-apply-semantics"></span>

pVisor 以文件为粒度管理 Agent 的访问与修改：按路径限定可访问的内容，将工作区改动隔离保存，并支持审查和选择性接受。访问规则和执行结果直接对应文件与目录，便于检查 Agent 能访问什么、修改了什么。

## 限定访问与修改范围 {#access-scope}

OverlayCore 提供受管理的文件视图，文件策略定义只读输入、可写路径和禁止访问的内容；执行器负责限制进程绕过该视图访问宿主文件。具体隔离范围取决于所用执行器，见[执行器边界](../security/executor-boundaries.md)。

暂存用于隔离候选改动，不能单独替代访问控制。按任务配置访问范围，见[文件策略](../guides/policies/files.md)。

## 从暂存到接受改动 {#candidate-changes}

文件改动按 **Stage → Review → Apply／Drop** 的流程处理。Stage 是暂存机制，通过 `--safe` 或 `--stage` 启用，不是独立的 `stage` 子命令。

| 操作 | 作用 |
| --- | --- |
| **Stage：暂存改动** | Agent 读取基础文件，将修改保存在私有写层；后续工具调用能读到这些修改，写入不会直接改动目标工作区。执行成功、失败或被终止，都不会自动接受候选改动。 |
| **Review：审查改动** | 查看新增、修改和删除，以及执行结果、实际生效的控制与警告，决定接受哪些文件。审查本身不改变目标工作区。 |
| **Apply：接受改动** | 检查冲突后，将全部或指定路径的候选改动写入目标工作区；未选中的改动继续保留，可以分批接受。 |
| **Drop：丢弃候选** | 丢弃剩余的未接受改动；已丢弃的候选不能再 Apply，已接受的改动也不会因此撤销。 |

例如，一次执行修改了 `src/` 和临时文件，可以先审查，再只接受 `src/`，最后丢弃剩余候选。具体命令见[审查并应用改动](../guides/review-apply.md)。

如需保留当前候选状态并尝试其他方案，可在全部 Apply 或 Drop 之前使用[工作区检查点与分支](resource-reuse.md#state-scope)。

## 文件改动的处理规则 {#file-change-rules}

| 规则 | 说明 |
| --- | --- |
| 净变化展示 | 审查呈现最终的净新增、修改和删除；创建后又删除的临时文件不出现，重命名显示为删除加新增。 |
| 文件属性保留 | 合入不仅处理文件内容，也保留可执行位与符号链接目标，不将符号链接展开成目标内容；平台例外见下方限制。 |
| 分批与重复应用 | 选择性 Apply 接受所选路径及其子树；分批接受全部改动与一次全部 Apply 的结果一致，重复 Apply 已接受路径不产生额外改动。路径依赖见[选择性应用规则](../guides/review-apply.md)。 |
| 冲突与路径边界 | 所选范围内发现冲突时，在写入前拒绝该批次；未触碰路径的外部修改不阻止合入。目录删除会检查外部新增，路径被替换为指向工作区外的链接时拒绝越界写入。 |

## 适用范围与限制 {#scope-and-limitations}

- 工作区暂存不覆盖远程 API 调用、数据库写入或已发出的消息等外部影响，也不保护通过 `--mount SOURCE:write` 显式共享写入的宿主路径。
- Apply 是对目标工作区的实际写入，不能通过 Drop 回滚。
- 多文件 Apply 对外部编辑器不是原子操作，应用期间应停止其他写入者；中断后的恢复与冲突处理见[审查并应用改动](../guides/review-apply.md)。

HOME、VM 根目录等其他位置的写入见[暂存与存储](../reference/cli.md#暂存与存储)；macOS 符号链接等平台行为见[已知限制](../security/known-limitations.md)。

完整的 Stage／Apply／Drop 行为，包括全部 Apply 与直接运行的结果对照，见[语义规格（未审核草稿）](../cases/06-stage-apply.md)；用例验证与人工审核的区别见[测试与 semspec](../community/testing.md)。

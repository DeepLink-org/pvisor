# 配置 512 MiB 的 VM，实际占多少内存？

## 主要结论 {#conclusions}

**配置 512 MiB 不等于宿主立即占用 512 MiB。在这组 64 MiB 应用工作集的静态测试中，默认 VM 与管理进程实际常驻约 178–182 MiB；内存卸载后约 35 MiB，每实例节约 80.1–80.5%；压缩卸载后约 40 MiB，节约 77.6–78.2%。包含文件缓存的产品组占用则从约 220–224 MiB 降到 19–25 MiB。** 每个条件测一次，结论限于当前 Linux 配置与短观察窗口。

| 用户选择 | 这组数据说明什么 |
|---|---|
| 内存卸载 | 每实例节约 80.1–80.5% 常驻内存；含缓存的组占用也下降，下一次工具需要恢复 RAM |
| 压缩卸载 | 卸载后每实例节约 77.6–78.2% 常驻内存；更省磁盘 backing，停驻常驻约 40 MiB |
| 空闲释放 | 每实例节约 33.9–35.2% 常驻内存，但宿主仍保留文件缓存 |
| 内存压缩 | 每实例常驻占用增加 183.8–209.8%，这组静态数据未体现节约 |
| 多实例共享 | 四台各配置 512 MiB，相同内容平均每实例节约 58.7–60.3%，各自独有随机内容节约 14.5%；完整改写后节约 13.0–15.1% |

## 实验动机 {#motivation}

512 MiB 是 guest 可使用的容量，不是 VM 在宿主上已经占用的物理内存。选择压缩、卸载或共享时，需要看实际宿主占用，以及下一次工具的恢复代价。只看 guest 空闲量或压缩率，都不足以判断机器省下了多少 RAM。

## 实验设计 {#interpretation}

<a id="experiment-design"></a>

所有 VM 固定为 **512 MiB guest RAM、2 vCPU、64 MiB 应用数据**。工作集保持一致：实际占用取决于触及的页面，因此不假设默认 VM 会用满 512 MiB。

**空闲释放**由应用主动释放测试工作集，VM 继续运行，需要再次使用时重新生成数据。**内存卸载**暂停 VM，将 RAM 状态保留在未压缩的 backing 中并卸载常驻 RAM，恢复后继续执行。**压缩卸载**使用压缩 backing 保存相同状态，减少存储占用，增加压缩和解压的代价。

- 单实例比较默认运行、空闲释放、内存压缩、内存卸载/压缩卸载。重复与确定性随机数据覆盖易压缩和难压缩内容；默认/内存压缩额外测可压缩的不同页面及 16 MiB 热区＋48 MiB 冷区。
- 跨实例从同一 sealed 快照恢复四台 VM，对照共享基线与相同字节的独立 inode 副本，并检查 25%/100% 工作集改写和独立退出。KSM 开关另设动态私有页对照。
- 每格一个新 VM 或新组，零预热。单实例观察 5 秒，跨实例扫描窗 2 秒；不报告 P50/P95、置信区间或最终收敛。

**常驻物理内存**统计完整产品组的 VM、管理进程、压缩池和辅助进程，使用进程 PSS 之和，共享页面按比例计算。**宿主组内存**使用完整 cgroup 的物理内存计费，包含计入该组的未映射文件缓存和内核开销。两个口径不能相加：前者回答进程实际常驻多少，后者防止忽略仍占 RAM 的缓存；共享页的归属方式也不同。两者都不等于整机新增的独占内存或生产容量。

Linux x86_64/KVM，AMD Ryzen 7 9700X，宿主内核 7.2.8-200.fc44.x86_64。完整组绑定逻辑 CPU 0–3、四核配额、2 GiB 上限、零 swap；协调器、观察者和全局 KSM 线程在组外。输入预先准备，不驱逐全局缓存；后台编译有记录，耗时仅为单次观察。全部 28 个条件通过数据、写入隔离、退出和来源检查，没有 OOM。部分独立基线条件触及 2 GiB 组上限，缓存受到回收压力。

下面的命令设置 512 MiB VM 并开启对应功能。将 `JOB`、`SOCKET`、`ATTEMPT` 替换为启动输出中的身份。内存卸载从普通 VM 启动；压缩卸载先启用压缩 backing。内存压缩需要 userfaultfd 权限，压缩 backing 需要 FUSE。

```bash
# Default 512 MiB VM
pvisor run --executor vm --memory 512MiB -- claude

# Memory compression
pvisor run --executor vm --memory 512MiB --vm-cold-ram-compression -- claude

# Compressed backing for later offload
pvisor run --executor vm --memory 512MiB --vm-ram-compression -- claude

# Use the identities printed at startup
pvisor suspend JOB --vm-socket SOCKET --vm-job-id JOB --vm-attempt-id ATTEMPT --vm-offload
pvisor resume JOB --vm-socket SOCKET --vm-job-id JOB --vm-attempt-id ATTEMPT --vm-load

# KSM advice: restored private COW RAM is eligible; fresh shared RAM is skipped
pvisor run --executor vm --memory 512MiB --vm-ram-dedup -- claude
```

普通新 VM 的共享 RAM 不接受这条 KSM 建议；恢复的私有 COW RAM 才符合去重测试条件。共享基线数据也不代表四次独立 `run`。内存压缩与 RAM 去重不能组合，恢复的私有 COW RAM 不支持上述 live offload。详见[控制选项](../../reference/cli.md#vm-instance-control)和[去重建议](../../reference/cli.md#vm-ram-dedup)。

## 实验数据和分析 {#results}

<a id="experiment-data"></a>

### 一台 512 MiB VM {#measurements}

每格 N=1，操作后 5 秒读数，单位 MiB。节约比例 =（默认实际常驻 − 当前实际常驻）÷ 默认实际常驻 × 100%，以相同工作集的默认运行作基准，用未舍入读数计算。512 MiB 是配置容量，不作为节约比例的分母。

| 方式 | 配置容量 | 实际常驻物理内存<br>重复内容 / 随机内容 | 每实例常驻节约比例<br>重复内容 / 随机内容 | 宿主组内存，含缓存<br>重复内容 / 随机内容 |
|---|---:|---:|---:|---:|
| 默认运行 | 512 | 178.0 / 182.1 | 基准 | 220.2 / 224.1 |
| 空闲释放 | 512 | 117.7 / 118.0 | 节约 33.9% / 35.2% | 223.5 / 219.9 |
| 内存压缩 | 512 | 505.2 / 564.3 | 增加 183.8% / 209.8% | 489.9 / 548.6 |
| 内存卸载 | 512 | 35.4 / 35.5 | 节约 80.1% / 80.5% | 19.4 / 19.1 |
| 压缩卸载 | 512 | 39.8 / 39.7 | 节约 77.6% / 78.2% | 24.8 / 24.4 |

**重复内容**：64 MiB 应用数据由固定的字节序列反复填充，容易压缩，用于观察内容重复时的节约效果。**随机内容**：相同大小的数据由固定种子的伪随机序列填充，难以压缩，用于观察内容缺少重复时的效果。两种工作集的数据量相同，表头中的顺序对应每格的左右两个数值。

空闲释放后，常驻降至约 118 MiB，但含缓存占用仍约 220 MiB，因此不能宣称宿主已净回收同样多的 RAM。内存卸载同时降低两个读数，收益更明确。

内存压缩组操作前常驻约 564 MiB，5 秒后重复内容为 505.2 MiB；这是该模式自身的变化，不能替代与默认 178.0 MiB 的比较。压缩不同页面时为 509.2 MiB，冷热混合为 517.8 MiB；对应默认常驻为 177.2 / 179.9 MiB。512 MiB 只限制 guest 容量，VM 外的管理和压缩机制也需要宿主 RAM，所以实际常驻可能超过配置容量。

### 卸载的存储与恢复代价

每格 N=1，耗时单位为 ms。先对比同样闲置 5 秒后、不卸载的默认 VM 执行相同测试任务的耗时。任务耗时从宿主发起操作开始，到完成 64 MiB 数据摘要、写入/fsync/读回校验为止；卸载组包含恢复 RAM 的时间。增加的耗时 = 卸载后任务耗时 − 相同工作集的不卸载任务耗时，使用未舍入读数计算。这是后台编译下的单次观测差值，不是稳定延迟保证。

| 方式 | 不卸载任务耗时 ms<br>重复内容 / 随机内容 | 卸载后恢复并完成任务 ms<br>重复内容 / 随机内容 | 增加的耗时 ms<br>重复内容 / 随机内容 |
|---|---:|---:|---:|
| 内存卸载 | 299.6 / 333.2 | 444.7 / 388.2 | +145.0 / +54.9 |
| 压缩卸载 | 299.6 / 333.2 | 621.6 / 642.2 | +322.0 / +308.9 |

卸载操作发生在进入闲置状态时，另列如下；backing 为实际分配的磁盘块，单位 MiB。

| 方式 | 卸载操作 ms<br>重复内容 / 随机内容 | backing MiB<br>重复内容 / 随机内容 |
|---|---:|---:|
| 内存卸载 | 41.1 / 103.4 | 186.3 / 186.7 |
| 压缩卸载 | 749.5 / 924.4 | 15.5 / 146.1 |

压缩 backing 在重复内容上更省存储，但需要编码、解码和临时内存。不要按停驻时的读数设置整个任务的内存上限；峰值、阶段 CPU 与完整样本口径保留在 CSV。

### 四台各 512 MiB 的 VM：共享快照基线 {#linux-lifecycle}

测量 pVisor 从同一快照恢复四台 VM、共享只读 RAM 基线并以写时复制（COW）隔离修改的收益。独立对照使用相同快照字节的四份独立文件；两组均未启用 KSM advice，也未连接外部共享压缩冷页池。

总配置容量为 2048 MiB。每实例实际常驻取完整组常驻合计 ÷ 4，包含分摊的辅助进程开销，共享页按比例计入。每格 N=1，单位 MiB；节约比例相对于相同工作集、相同阶段的独立基线，用未舍入读数计算。

| 工作集 | 独立快照每实例常驻 | 共享快照每实例常驻 | 每实例节约比例 | 100% 改写后每实例节约比例 |
|---|---:|---:|---:|---:|
| 相同重复内容 | 104.7 | 41.6 | 60.3% | 13.8% |
| 相同随机内容 | 104.2 | 43.1 | 58.7% | 13.0% |
| 各实例独有随机内容 | 106.9 | 91.5 | 14.5% | 15.1% |

例如，相同重复内容的平均每实例实际常驻从 104.7 MiB 降至 41.6 MiB，节约 60.3%。完整改写后，独立/共享组常驻合计为 426.4 / 367.4 MiB，对应每实例 106.6 / 91.8 MiB，节约 13.8%。改写后的比例使用改写后的独立基线。

相同内容最能保留共享；独有随机数据会在准备阶段增加私有页，改写也会削弱收益。重复内容的独立/共享组含缓存占用为 2035.7 / 841.2 MiB，与常驻读数 418.8 / 166.4 MiB不同。基线存储缓存确实消耗 RAM，但不能把它全部当作 VM 的常驻工作集，更不能把这个比值直接换算为可运行台数。

KSM 是另一个独立对照，作用于恢复后产生的动态私有页。KSM advice 关/开常驻读数分别为：重复 363.5 / 362.1 MiB、相同随机 367.8 / 361.3 MiB、独有随机 366.1 / 365.0 MiB。2 秒、单次样本不足以确认额外收益，也不能证明 KSM 无效。外部共享压缩冷页池（`--vm-memory-pool`）尚无这组 512 MiB 配置的测量；当前 Linux pager 仅支持实例本地压缩存储，外部池需要 Apple Silicon macOS，见[实验冷页池](../../design/memory-optimization/proof-of-concept.md#v1-integration)。数据不回答长期稳定性、真实 Agent 延迟、macOS 或其他运行时的密度比较。

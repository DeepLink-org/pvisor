# 核心机制

pVisor 的运行内核把一次任务组织成四个部分：执行环境、访问边界、生命周期和结果。调用方提供命令与策略，内核准备资源并监督执行，任务结束后留下运行记录；启用暂存时，文件改动由调用方另行审查和接受。

本地 CLI 与嵌入调用共用执行路径。单节点 daemon 在独立 supervisor 中调用原生 VM 执行，并提供沙箱生命周期 API。跨节点的主机选择、队列与业务重试由外部编排负责。

## 系统模型 {#architecture}

```text
CLI / 嵌入调用 / Daemon supervisor
              │
       执行请求与有效策略
              │
       Session 生命周期管理
              │
    ┌─────────┼─────────┐
  执行器    文件服务   网络服务
    └─────────┼─────────┘
              │
       结果、观察与运行记录
              │
       调用方验收与成果处理
```

执行器提供进程、容器或 VM 环境；文件与网络服务在各自的数据路径落实访问策略。Session 将这些组件组织成一次受管理的执行，负责资源准备、取消、清理和终态公布。

共享类型和纯策略求值放在 `pvisor-core`，运行与平台机制由 `pvisor` 及驱动实现。Gateway、TUI 和 Replay 在这个基础上增加模型通信、交互和轨迹处理。组件归属、宿主控制协议与服务接入细节见[核心架构](architecture.md)。

## 一次任务如何完成 {#execution}

1. **准入。** 检查请求、执行器能力和平台前提，得到有效策略与执行位置。
2. **准备。** 建立文件视图、网络接入和运行资源，提交必要的启动事实。
3. **执行。** 启动命令，通过运行句柄接收取消与控制请求，并收集输出和观察。
4. **收尾。** 清理受管理资源，检查控制结果，保存运行记录并公布终态。
5. **验收。** 调用方检查执行结果；启用暂存时，再决定接受哪些文件改动。

执行完成、资源清理和成果接受各有结果。命令失败仍可能留下有用文件；取消后要等待停止与清理结果；记录失败时仍需核对已经发生的效果。

Job 是用户持续操作的一项工作，Attempt 标识其中一次执行，Operation 描述处理请求，Event 记录观察到的事实。具体身份、状态与恢复关系见[执行模型](execution-model.md)，事件链和提交语义见[Operation 与 Event](operations-events.md)。

## 访问与改动如何处理 {#boundaries}

文件服务将工作区基底和任务私有改动组合成执行视图。启用暂存后，写入先保留在私有层，apply 再按选定路径检查冲突并写回工作区。host FUSE 与 VM virtio-fs 共用文件语义，入口分别处理各自的协议和平台要求。写时复制、冲突基线及部分发布恢复见[OverlayCore](overlayfs.md)。

网络服务在代理或 VM 数据面检查目标和权限，Gateway 可进一步处理模型请求。实际覆盖取决于执行器和接入方式，因此记录分别保存请求策略、安装的控制和运行观察。网络路径见[OverlayNet](overlaynet.md)，各执行环境的保护范围见[隔离机制](isolation.md)。

## 状态与资源如何复用 {#resources}

镜像提供环境的只读输入，任务写入保持独立。共享镜像缓存固定内容版本，按需读取索引和文件块，减少预先展开整个镜像的需要。小文件打包与读取合并属于 Lazy Image V2 提案；当前格式和实现见[共享镜像缓存](shared-image-cache-storage.md)。

内存优化分别处理重复内容、冷工作集和闲置环境：共享减少副本，压缩减少保留体积，卸载把内容转移到可恢复存储。选择机制时同时考虑恢复来源、CPU、峰值内存和下次任务等待，具体组合与平台状态见[内存优化](memory-optimization/index.md)。

## 结果如何保留 {#results}

运行记录连接请求、有效策略、实际控制、退出结果和产物。Job 元数据用于定位工作，Bundle 用于审查结果，Journal 保留已提交事实；候选文件与冲突基线由文件层管理。事件写入、回执和恢复见[Journal](journal.md)。

恢复需要先明确保留了什么：文件检查点保存候选文件，Agent 轨迹保存历史上下文，执行检查点保存受支持 profile 的机器状态。远程 API、数据库和消息等效果由业务侧协调。调用方据此选择重新执行、恢复环境或继续审查，避免把不同恢复路径混用。

## 关键取舍 {#principles}

- **统一合同，平台机制各自实现。** 调用方使用共同的请求和结果模型，驱动报告支持能力及实际控制。
- **生命周期集中，数据路径分工。** Session 管理一次执行的资源与终态，文件、网络和 VM 组件管理各自的访问路径。
- **执行与成果发布分开。** 运行结果用于判断任务发生了什么，文件验收决定哪些改动进入目标工作区。

这些取舍对应的开发约束、因果规则和证据要求见[核心设计原则](principles.md)。

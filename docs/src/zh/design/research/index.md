# 研究方向

OS 与 MLSys 研究要回答的是：在固定资源下，有边界的执行与保留的证据能否降低批量运行、评估 Agent 的成本。外部编排接入仍处于接入研究阶段，Agentic RL 执行基座仍属规划；两者对应[信任阶梯](../../why/trust-ladder.md)的 L2–L3，尚待工作负载验收与测量。

## 执行与编排的所有权

pVisor 拥有单次执行的边界与观察。外部编排拥有主机选择、队列、依赖与重试；训练器还拥有采样、奖励和评估器版本。[单节点 daemon](../daemon/index.md) 管理本机 VM sandbox 与服务访问，不暴露原生 Job 暂存、检查点或 Run Bundle 导出。因此，要支持这些研究工作流，其 API profile 还需要显式的执行／证据交接。

拟议接入将编排侧工作身份绑定到本机 Job/Run/Attempt 或 sandbox 身份，固定输入与运行时版本，并将结果与对应制品一起收集。结果未知时先核对再重试：超时不证明工具或远程副作用从未执行。[外部编排研究](cluster-execution.md)细化这一边界，不提出产品自有集群调度器。

## 状态复用与评估

文件检查点复用候选文件与冲突基线，Agent 轨迹保留上下文和工具历史，受支持的 VM execution 检查点保留其 profile 捕获的机器状态。三者是实验中的独立输入。工具重执行会产生 fresh observation，远程服务状态和训练器 metadata 需另行处理。[RL 执行基座提案](rl-execution-substrate.md)将执行成功与任务奖励分别判定。

先独立记录并评估一次 attempt，再用分离的 workspace 与记录增加并发。声称训练前缀可复用之前，分别验证前缀准备、工具回放和模型续跑。RL 框架接口、rollout 吞吐与共享前缀收益仍需接入和测量。

## 收益需要什么证据

固定任务、输入、输出检查、模型服务容量和总资源预算，测量正确完成量、首个结果与恢复长尾、整组内存、checkpoint/fork 成本和审查工作量。计入准备、收集、存储与恢复开销，不仅按就绪时间或压缩率给机制排名。

共享不可变状态可能减少重复成本，但私有写入、冷缺页和恢复缓冲可能抵消收益。故障实验须保留未知结果，区分本机清理与业务副作用核对。旧 Controller/Worker 测量和原生机制探针不建立当前 daemon 密度或跨主机恢复能力。

[公开研究产出](publications.md)的来源和实验范围与实现保证分别保留。目前尚未登记正式论文、外部报告或演讲。

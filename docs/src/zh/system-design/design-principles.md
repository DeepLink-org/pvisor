# 设计原则

这些原则解释了文档为什么强调可审查的步骤。

## 边界必须明确

pVisor 描述实际安装的执行边界。它不会把缺失的控制默认为更强的保证。

## 审查前的写入应可逆

Agent 的 Effect 在人或明确策略应用前保持 staged。审查是工作流的一部分，不是写入完成后才补上的报告。

## 结果必须带着证据走

汇总应该能回到产生它的 Run。只有在再次检查之后仍保留 lineage，它才真正有用。

## Capture 保持可选

pVisor 可以不打开模型流量捕获而运行。打开之后，capture 是写入同一次 Run 的窄交接，不是第二个产品。

## 可移植数据优先于特权查看器

Run 记录应该可以通过 CLI 和公开格式检查。Web 界面可以改善发现，但不应成为恢复答案的唯一方式。

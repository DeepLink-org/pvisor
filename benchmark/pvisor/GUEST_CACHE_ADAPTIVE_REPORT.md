# 稀疏访问与批量元数据访问能同时加速吗？

## 主要结论

**保守自适应准入收回仅枚举版的大部分批量访问退化，同时避免首个 lookup 导入全目录。它仍有明显残余代价：相对原始激进预取，宽目录全量访问 51.418 → 74.437 ms（约 +45%）；相对仅枚举版，32 个随机文件 1.933 → 5.540 ms。不能称为全部负载无退化。**

## Motivation

避免用整目录预取放大 Agent 的少量已知路径访问成本，同时恢复取消 lookup 预取后损失的批量 stat/read 与有效期收益。原始预取、仅枚举加载和候选同批比较，避免只选更慢的上版作为对照。

## 实验设计

- B-FS-ENG；相同冻结 release CLI、SDK、guest payload 和输入，三种固件均 guest cache=1、writeback=0。原始预取为 `561b4ccf`，仅枚举为 `d55fb807`，候选 `bbed1fcf` 含补丁 0045；三个内核实际配置相同。程序未变，macOS release 使用随程序分发的 dylib。
- 上述编号保留测量时的补丁布局。当前源码已将原 0044/0045 合并为 `fw/patches/0044-fuse-adaptive-directory-prefetch.patch`，应用后的内核源码逐字节一致；冻结源码、制品和收据保持原样。
- Apple Silicon/HVF，每 VM 2 vCPU/4096 MiB；宿主热缓存，新 VM/upper。普通 --safe CLI（Mutable lower）与 SDK Immutable share 分开统计；没有宿主 CPU affinity/cgroup 或无外部干扰的保证。保留用户已有 Host listener。
- 每臂 3 warmups/30 正式样本，每轮六条件 seeded shuffle（20261018），共 198 个正常退出并校验成功的 VM。没有剔除慢有效样本。各候选/参考分别配对 bootstrap 5000 次，先检查分布；分离簇列比例与中位数，不作整体排名；没有 P99，没有多指标校正。
- 原有 13 阶段保持顺序：2048 路径 stat、深路径、扫描、64 MiB 全字节验证读取、热 open、单文件宽目录访问、空闲 1.3s 后 stat。新增四个独立 2048 项宽目录，分别访问两个远隔名字、32 个乘法置换名字、32 个步长 61 的名字、全部名字。新阶段在原有阶段之后，不污染其缓存状态。
- metadata 文件为 8 字节；读组为 2048×32 KiB。原生 TTL 为 1s，导入元数据为 24h，因此过期组包括期限策略收益。完整 fixture/rootfs/程序/固件摘要在前后校验；fixture 为 APFS COW 副本，未使用会改变 --safe 行为的硬链接。每个 CLI Bundle 也验证正常 VM 执行。
- B-FS-DIAG 单独运行三臂共 90 个 VM，包含 prime-only 差分和完整负载；计数任务耗时不混入计时样本，所有 instance 有 final_record，并执行策略断言。

### 实现边界

- 目录大小仅作准入提示，要求 4–64 次连续不同名字的缺页；名字哈希碰撞只会延迟预取，不参与名字解析或权限判断。当前宽目录提示为 64，小目录为 4。其他宿主文件系统的目录大小语义尚未标定。
- 初始窗口四个客机页（当前 16 KiB）。只取一页，不为寻找当前名字连续追页；窗口没有当前名字就停止推测性预取。窗口有用且已有正 dentry 及导入 inode 的首次命中计数达到窗口项数四分之三后，才将下一窗口扩到协商预算，最多 1 MiB。
- 首次命中用 inode 位和父 inode 计数记录，包含 RCU 路径；不持有目录镜像/子 dentry 引用。计数是性能提示，不承担正确性。并发 lookup 避开未完成的导入；触发项消费引用前验证 inode ID/属性。
- 不完整镜像发生 guest 命名空间变更时失效并回退宿主，防止分页 cookie 错位。显式 readdir 仍可完整导入；ENOSYS 按连接记忆，惰性 open 保留。
- 该策略没有对任意访问分布作无退化保证；从大目录中部开始的扫描、命中率不足或不适合该大小提示的目录可能保持按需路径。未引入后台工作线程、宿主协议或新用户开关。

## 实验数据和分析

单位 ms；每臂 n=30。普通值为中位数，分离分布列簇比例/中位数。CI 为自适应减对应参考。

相对仅枚举版，SDK 首次 stat 136.870 → 64.011 ms、深目录 189.563 → 108.528 ms、64 MiB 首次读取 463.025 → 391.671 ms、到期 stat 144.993 → 5.641 ms；对应配对 CI 均小于零。相对原始预取，首次 stat 60.631 → 64.011 ms，配对 CI [1.243, 12.226] ms，为残余退化；首次读取未检出差异。

随机/跨步访问相对原生按需路径仍有约 3–4 ms 代价，连续大目录相对激进预取仍有约 23 ms 代价；小窗口限制回复和属性量，但宿主仍需枚举目录名字，不能作为恒定 CPU 成本上限。

### 为什么没有采用更早探测

另一个独立完整批次 `.data/guest-cache-adaptive-bounded-formal-20261016/` 比较所有目录第 4 次缺页即探测的小窗口策略。该批同样 198 个 VM、30 正式样本/臂，并独立通过 90 个诊断任务。它相对自己同批的仅枚举控制，将全量访问 124.552 → 62.382 ms，却将随机 32 个文件 1.999 → 19.899 ms（差异 CI [17.417, 18.305]），跨步 32 个文件 1.991 → 13.490 ms。此方案未选入 release。两个批次没有合并样本，也不以跨批绝对时间给参数作配对排名。

保留较晚准入是对稀疏/随机成本的选择；它没有消除宽目录连续访问相对原始预取的全部差距。需要进一步降低此差距时，宿主目录分页/快照构建成本也是优化对象，不能只继续提前预取。

### 独立请求数验证

以下是相对 empty VM 的协议请求增量。完整 VM 差分可有少量 rootfs 噪声，不能当逐请求 trace；所有结论由源码路径与计数联合确认。

| sdk / 仅枚举 | 0 | 0 | 0 | 0 | 0 / 2049 | 2083 |

SDK 自适应在读过 64 个前缀名字后，反复访问同一文件 1000 次再跳到远处，仅有 1 次 READINDEX；低利用窗口没有被这种重复访问误导而继续扩大。

三臂的 1000 次 open/fstat 均不增加 OPEN/READ/FLUSH/RELEASE，惰性 open 保留。普通 CLI 的目录镜像资格没有改变，不能将 SDK 的批量收益外推为普通 CLI 或整个 Agent 的收益。

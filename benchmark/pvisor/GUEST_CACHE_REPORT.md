# Guest 目录镜像和惰性 open 的工程对照

此页保留修复前的开关对照；按需加载修复的独立最终固件对照见
[GUEST_CACHE_DEMAND_REPORT.md](GUEST_CACHE_DEMAND_REPORT.md)，两批数据没有合并。

## 主要结论

**普通 `--safe` CLI 的明确收益来自只访问元数据的惰性 open；目录镜像在该工作区不满足启用资格，首次深目录 stat 还出现退化。显式不可变 share 的目录访问可以受益，但宽目录稀疏访问有整目录预取代价。**

这两个 cohort 分别比较同一制品的开关，不把 SDK 与 CLI 的绝对耗时当成实现排名。全部 120 个正式任务及 12 个预热任务通过退出、元数据和内容校验，未剔除慢有效样本。

## Motivation

判断现有 guest 目录镜像、惰性只读 open 是否比当前 Linux/FUSE 缓存配置更适合 Agent 的文件访问；分开识别批量目录访问、仅打开元数据和真实读取的收益与代价。

## 实验设计

- Apple Silicon/HVF；每个 VM 2 vCPU、4096 MiB。宿主热缓存，每个 trial 新 VM、新 upper/work。没有宿主 CPU affinity/cgroup 或无外部干扰的保证。
- 固定同一固件 `561b4ccf`；每个 cohort 固定一个 release 主体，仅切换 `PVISOR_VM_GUEST_CACHE=0/1`。writeback 固定为 0，不启用 DAX。普通 CLI 保留 `--safe` 网络/文件策略；SDK 使用相同 VM/Overlay 实现，显式声明 subject lower 为 Immutable，rootfs 仍普通 Mutable。
- 两个 cohort 每臂 3 次预热、30 次正式运行；每轮对四个条件 seeded shuffle（seed 20261017），各自作配对 bootstrap（5000 次）。逐项检查分布，分离簇只给各簇比例和中位数，不作整体排名。没有 P99。
- 32 目录/2048 文件；stat/枚举组每文件 8 字节，读组每文件 32 KiB（共 64 MiB）。深路径每分支额外七级目录；宽目录单层 2048 项。各负载使用不同目录，预备路径列表不访问 guest 文件系统。
- 立即重复 stat 的首次加重复访问总时长均小于原生 1s TTL；到期组明确空闲 1.3s。热 open/fstat 先在计时外 prime 元数据；open/read 先 prime 内容，再每次重开读取 4 KiB。64 MiB 的全量字节验证在读阶段计时外，open/read 的小块验证在循环内。
- 关闭组保留当前 Linux dentry/inode、页缓存和 FUSE 默认策略，不是关闭所有缓存。SDK 两臂已有相同物理 Immutable 缓存；未比较“调长 TTL 或开启原生目录缓存后的最佳 FUSE 配置”。目录镜像使用更长属性有效期，所以过期组收益包含有效期策略差异。
- CLI 使用同一冻结工作区，payload 只读；每次独立 stage/Run Bundle 并验证 VM 隔离、正常退出和 staged 状态。准备前后全量核对 fixture 和 rootfs 内容、模式、符号链接以及二进制/固件摘要。没有修改或替换已有 Host 服务。
- 独立 36 个 profiling VM 服务 B-FS-DIAG；prime-only 差分比较请求数，所有 profile instance 的最后记录完整，profiling 时间不进入下表。

### 请求数验证

以下为一个独立完整 profiling 批次的 prime-only 增量；元数据与真实读取有不同的宿主成本。两种 cohort 的这些计数一致：

| 1000 次操作的宿主增量 | 关闭 OPEN / READ / FLUSH / RELEASE | 开启 OPEN / READ / FLUSH / RELEASE |
|---|---|---|
| open/fstat/close | 1000 / 0 / 1000 / 1000 | 0 / 0 / 0 / 0 |
| open/read/close | 1000 / 1000 / 1000 / 1000 | 1000 / 1000 / 1000 / 1000 |

宽目录 sparse 的独立增量：SDK 关闭为 2 LOOKUP，开启为 2 READINDEX、0 LOOKUP；普通 CLI 关闭为 2 LOOKUP，开启为 1 READINDEX、2 LOOKUP。结合冻结源码中 `supports_directory_image` 要求全部 lower 为 Immutable，以及普通 CLI 的 Mutable 声明路径，可确认普通 CLI 的 READINDEX 尝试没有替代实际 LOOKUP。

立即重复 stat 两臂都无新增 subject LOOKUP/OPEN；完整 VM 差分可有约 1 次 rootfs GETATTR 噪声，不将该差分当作单文件精确 trace。空闲后 SDK 开启能保留目录镜像元数据，而普通 CLI 两臂仍有约 2091 次 LOOKUP 增量。

### 工程含义

1. 热 stat 的原生缓存已经有效；不能把关闭组仍然快解释成开关失效。惰性 open 主要帮助只做元数据检查后就关闭的文件；真实 read 会绑定宿主句柄。
2. 日常 CLI 的目录镜像资格仍未接通：开关开启不等于工作区已满足 Immutable 承诺。应先明确传递独占/不可变承诺，再谈 CLI 的目录镜像收益，不能直接将所有普通宿主目录标成 Immutable。
3. 完整扫描与只访问一个名字有相反需求。宽目录首个 lookup 触发全部目录项预取，对稀疏访问有显著代价；后续设计应区分按需 lookup 和批量扫描。
4. 重开读取还受 KEEP_CACHE、属性期限和宿主逐文件协议约束。这个实验不证明自研缓存优于调优后的原生 FUSE 缓存，也不比较 Kata、ext4、磁盘冷缓存、Linux/KVM 或完整 Agent 任务。

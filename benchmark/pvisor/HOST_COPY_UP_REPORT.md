# 宿主 copy-up 是否还会阻塞 metadata

Benchmark：**B-FS-ENG / engineering A/B**。结果仅属于宿主调度改动，不更新用户文件系统性能排名。

## 主要结论

**在 Apple M4、APFS、macFUSE FSKit 5.4.0 的 1 GiB 文件复制阶段，首次 stat 的中位数从约 800 ms 降到 0.68–1.65 ms。writable-open 中位数未检出差异；开启 compact strict 日志时，空闲的 64 路径 metadata 批次回退 1.90 ms（5.92%，95% CI 2.30%–10.74%）。**

| 判断对象 | 结论 |
|---|---|
| 大文件 copy-up 期间的短请求 | 阻塞明显降低，两种日志配置的置信区间均排除零差异 |
| writable-open 中位数 | 两种配置均未检出差异，不能宣称复制本身加速 |
| 空闲 metadata | 无日志未检出差异；strict 日志测出约 6% 的批次回退 |
| 尾延迟 | 样本数不足以判断稳定尾部，无日志候选组存在较慢 open 样本 |

这项改动解决了复制阶段的响应性问题。strict 日志下日常 metadata 的成本仍需要单独定位；当前数据没有给出原因。

## Motivation

一个 writable-open 可以触发大文件 copy-up。在宿主请求线程独占处理时，其他文件的 stat 也要等复制完成，交互工具会出现与自身工作量不相称的等待。工程对照需要同时确认短请求是否恢复响应、大文件操作是否回退，以及不发生 copy-up 时的额外成本。

## 实验设计

- 同一实际工作树冻结两份源码，A 仅将十个宿主/prepared-copy 源文件恢复到 `392c9d99b2044e1b25bfafd789e93eb297d8e82f`，B 保留改动；VM 的已有改动在两份源码中相同。源码差异清单由构建收据校验。
- 同一离线 release 构建、编译器、依赖 lock、mount driver 和 harness。调用真实宿主 API，默认 mutable lower、默认内核缓存，不启用 profile、metrics 或自定义访问策略。
- Apple M4，24 GiB 内存，Darwin 27.0.0 / arm64；lower、upper、work 均在 APFS。macOS 调度器管理 CPU，没有固定亲和性、内存限额或全机独占预算。
- 同一个预准备的 1 GiB 非稀疏确定性文件；不清空宿主页缓存。每个试次使用新的 mount、upper、work 和 journal。`nojournal` 与 `compact` strict 日志分别统计。
- 每个条件/制品三次预热、三十个正式样本；固定 seed 4207，每轮随机排列条件及 A/B 顺序。共 132 次受校验挂载，其中正式样本 120 个。预检不计入。
- 先测 64 条独立 `idle` 路径，然后启动大文件 writable-open。观察到真实临时文件满足 `0 < size < 1 GiB` 后，立即 stat 尚未查询的 `probe` 路径；记录第一条 stat 和全部 64 条 stat 的 wall time。
- `open_ms` 从发起 writable-open 到返回，包含协议、基线指纹、复制、发布与返回。它不是纯 byte-copy span。metadata 的触发点在字节复制开始之后，因此不测之前的基线指纹等待。
- 每个试次在计时后完整检查 upper/lower SHA-256、lower 身份及元数据（允许读取引起的 atime 变化）、硬链接、已打开描述符、rename、临时副本清理和正常卸载。66 份 compact 日志另经独立 frame/checksum 解析，`slow` 的首次指纹均与原文件 SHA-256 一致。
- 在每个试次前、每 250 ms 和试次后检查可见构建/测试进程，记录 1,158 次中途检查，未检出干扰。检测到干扰、错误或未命中复制窗口会使批次失败；不剔除慢有效样本。采样不能证明没有短暂或不可见的宿主活动。

正确性失败、正式样本剔除均为 **0**。按仓库的分布拆分规则，八组指标均未形成满足条件的两个簇。差异使用 5,000 次按配对轮次重采样的 bootstrap；区间包含零时报告“未检出差异”。P95 仅作描述，不报告 P99。

本实验不回答 Linux 真挂载、冷磁盘、大目录发布、多个 copy-up 并发、基线指纹阶段响应性、整个 staged 任务或 git/npm/Cargo 工具总耗时。

## 实验数据和分析

下表每个 A/B 单元均为 **N=30**，时间单位 **ms**，数值为 P50。百分比为候选相对基线的变化，负值表示耗时降低；95% CI 为配对 bootstrap。

| 日志配置 | 指标 | A：改动前 | B：改动后 | 中位数变化 | 95% CI（变化比例） |
|---|---|---:|---:|---:|---|
| 无日志 | 复制期间首次 stat | 802.86 | 0.68 | −99.92% | [−99.919%, −99.911%] |
| 无日志 | 复制期间 64-path metadata | 836.94 | 21.00 | −97.49% | [−97.55%, −97.42%] |
| 无日志 | writable-open | 803.73 | 819.46 | 未检出差异 | [−0.90%, +4.09%] |
| 无日志 | 空闲 64-path metadata | 34.56 | 34.60 | 未检出差异 | [−8.28%, +7.64%] |
| compact strict | 复制期间首次 stat | 790.32 | 1.65 | −99.79% | [−99.816%, −99.782%] |
| compact strict | 复制期间 64-path metadata | 827.03 | 34.64 | −95.81% | [−95.85%, −95.74%] |
| compact strict | writable-open | 1,232.67 | 1,231.29 | 未检出差异 | [−1.28%, +1.47%] |
| compact strict | 空闲 64-path metadata | 32.16 | 34.07 | +5.92% | [+2.30%, +10.74%] |

两个配置中，候选的全部三十个正式样本在完成整个 64-path metadata 批次后，临时副本仍处于未复制完的状态。这直接支持短请求与内容复制重叠；基线的首次 stat 等到复制结束，等待接近当时剩余复制时间。

strict 日志的空闲 metadata 差值为 **+1.90 ms**，95% CI **[+0.76, +3.36] ms**。这是一次 64 路径批次的成本，不是每条 stat 增加 1.90 ms。不能把改善复制时的等待解释为日常文件系统全面加速。

open 的中位数差异区间分别为无日志 **[−7.33, +32.76] ms**、strict 日志 **[−15.88, +17.95] ms**，均包含零。尾部仍有不确定性：

| 日志配置 | A open P95（参考，ms） | B open P95（参考，ms） | A/B 中超过 2 秒的正式样本 |
|---|---:|---:|---|
| 无日志 | 868.33 | 2,668.38 | 1 / 3 |
| compact strict | 2,075.71 | 2,251.85 | 2 / 2 |

所有这些较慢样本均保留。三十个样本的描述性 P95 不能证明尾延迟没有回退，也不能确定差异来自调度、存储或宿主状态。

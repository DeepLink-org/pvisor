# 四实例持续通信与故障恢复：通过项和拥塞限制

## Motivation

四实例在覆盖的持续流量和节点故障场景中保持了内容完整性、健康节点通信和故障后恢复。饱和 TCP 流量下，UDP 出现接收超时并需要重传；当前证据不能支持拥塞时无丢包、按时交付或数天稳定运行的保证。

独立的 30 分钟批次完成 1,892 轮混合流量、30 次故障检查、4,459,400 次 TCP/RPC 回包和 4,151,520 次 UDP 请求校验，未出现内容错误或 OOM，单实例宿主 cgroup 峰值 52.54 MiB。另一个 TCP/UDP 并发批次出现 81 次 UDP 接收超时，未通过预定的并发完成判据；该失败保留且未重跑。

## 实验设计

测量逐字节校验结果、故障中的健康节点可达性、恢复结果和实际资源边界，作为网络正确性及持续运行证据。这些证据描述指定负载与故障下的交付和隔离行为。校验失败越少、覆盖的场景与观察窗越充分，对相应场景的信心越强。

注册项为 [B-PEER-CHAOS-ENG](../README.md#b-peer-chaos-eng)，角色为诊断，不做性能比较。Linux/KVM 四 VM，各配置 384 MiB guest RAM，宿主独立 cgroup 硬限制 512 MiB、swap 0、1 CPU 配额、CPU 4–7；控制器 CPU 8–9。使用冻结的批量转发 CLI 和 firmware，22 个网络 Rust 文件与测前工作树逐文件一致；并行的 daemon/guest 改动未进入冻结运行时。来源、制品摘要和限制记录在原始目录。

持续批次交替运行全互连 TCP RPC、12 向共 384 MiB 批传输、四跳环形 RPC和慢读端，再检查 12 向、32–1,472 字节 UDP。每个 UDP 请求最多尝试八次，接收超时 250 ms，重传和重复回包单列。另有健康节点间三条 TCP 连接持续 1,800 秒交换变长数据，不允许重连。

每分钟轮换对节点 1 注入三秒 cgroup 冻结、正常停止/启动、SIGKILL VMM、删除后同名同 IP 重建。每个故障窗口检查其余三节点通信，恢复后检查全互连、UDP、环形通信和全部 12 向 DNS。节点 0/2/3 保留原进程，逐秒记录 cgroup、线程和 FD。任何意外失败停止批次，不剔除、不拼接。

持续批次的历史 TCP worker 在所有发送线程完成建连前输出 READY，因此该批次只证明请求跨越暂停/解冻后完成，不能证明注入时全部连接均已建立。worker 已增加独立建连屏障；使用新镜像的独立 30 秒补查验证了严格先建连后暂停，并重复四类故障，不与持续批次合并。

TCP/UDP 并发补充实验另启一组四 VM，原计划三个 384 MiB TCP 批传输同时检查 UDP，并要求 UDP 整批完成时仍有 TCP 客户端未完成。首轮不满足此判据即停止，未补跑。所有批次的预算相同；宿主有其他构建活动，持续批次 1,772 次采样中有 213 次记录到外部活动，未终止其他工作，结果不用于速度或时延归因。

| UDP | 4,151,520 次请求，尝试数相同，超时/重复均为 0 | 通过此负载 |
| DNS | 372 次正向解析检查 | 全部通过 |

TCP 前向载荷不重复计算回包及环形中继跳数；慢读端另有 3.70 GiB 校验流量未计入该值。持续批次与补查分别统计，没有由完成的局部数据补齐失败批次。独立审计核对了持续批次 15,618 份客户端原始输出、实际数量、制品摘要、资源事件及清理记录。

三个节点的 PID 和进程启动标识保持一致，观测期间 FD 总数最大值均为 127。冷态 FD 总数为 104、结束为 119，冷态尚未建立全部连接，不能将其直接作为稳态基线。窗口内未见持续明显增长，有限观察不能排除低速泄漏。cgroup 数值包含相应实例内被计费的 guest/VMM 等工作集，不是完整配置 RAM 的物理占用或整个宿主成本。

并发补充实验的 384 MiB TCP 数据和全部 UDP 内容均通过校验，但 UDP 发生 81 次接收超时并重传，完成时 TCP 客户端均已完成。因此不能把该实验记为通过，也不能宣称 UDP 在饱和 TCP 期间有交付时限保证。超时次数不是丢包率；未定位发生于 guest、virtio、Unix stream 或 peer datagram 的哪一段。现有设计采用有界缓冲、拥塞丢弃及上层恢复，不承诺 UDP 可靠交付。后续若改善混合负载，应先补逐段丢弃原因和队列观测，再评估拥塞隔离与调度。

公开接口测试还覆盖跨网络隔离、ARP/ICMP、伪造源/代际/路径、畸形与过长报文、guest stream 分片、接收端饱和、持续 flood 下 DNS/关闭公平性，以及真实 smoltcp 双向 1 MiB 在确定性丢包、复制和乱序中的恢复。这部分使用宿主 socket 和模拟 guest 链路；不冒充真实 VM 的同类故障注入。

失败证据完整保留：最初预检用了缺少 `bulk-long` 命令的历史测试程序；一次持续批次在约两分钟时触发测试脚本读取已删除 cgroup 的竞态。这些批次均未记为通过。脚本竞态和 READY 屏障已修正，没有修改网络转发实现。历史启动退出码 125 的根因仍未定位，本次未复现不代表已修复。

覆盖范围为单机、四节点、一个故障节点和 30 分钟观察；未验证数天运行、多节点同时失效、内存压力注入或其他平台。测试实例和专用网络已清理；镜像、制品及原始证据保留用于复现。

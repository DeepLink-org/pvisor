# 修复后物理页池：四 VM 的内存与 CPU 取舍

## Motivation

这组完整预检显示，物理页共享能降低重复内容的占用，并在读回后保留共享；
代价是额外 CPU 和更长的完整读回耗时。数据改写为实例独有内容后，业务数据的
共享收益消失，映射及管理成本仍可能保留。这里报告单次观察，不宣布稳定性能改善。

相同随机内容在 60 秒时的整组计费内存从 off 的 470.16 MiB 降至 physical 的
292.25 MiB，同时该空闲窗口的累计组 CPU 从 0.363 秒升至 7.412 秒。
全量私有写后再观察 30 秒，physical 为 499.59 MiB，off 为 471.17 MiB。

## 实验设计

本报告属于 `B-MEMORY-SCALE` 的 engineering diagnostic，不替换用户 benchmark
正文。2026-11-15，Linux x86_64/KVM、Ryzen 7 9700X、
`7.3.3-300.fc45.x86_64`，使用重新构建并冻结的修复版静态 musl release。
KSM 全程保持 `run=0`，没有改动宿主设置或停止外部任务。

三种内容分别运行 off、physical，共六条件，每条件一个独立新组，N=1，
无预热，按固定种子顺序执行。每组四 VM，各 256 MiB / 一 vCPU / 64 MiB 数据；
完整产品组含 VM、池和组内控制器，限制四核配额、CPU 0–3、2 GiB、零 swap、
256 tasks。外部观察者及协调器在组外、CPU 4–5；预准备输入缓存不清空。

从全部就绪开始记录 60 秒空闲曲线，之后完整读回、25%/100% 私有写和 peer
校验；全量改写后再保留 30 秒，最后独立退出并校验存活实例。每条件 58 项
内容与生命周期校验，共 **348/348 通过**；24 个 VM 均正常退出，六个资源组
清理通过。连续干扰检查共 1,166 个观察点，**零外部 VM/编译/测试记录**；
三个 physical 条件的 12 个 VM 日志均通过发布健康检查，零停发事件。

计费内存是整个 cgroup 的 `memory.current`；PSS 是进程映射的比例分摊驻留量，
包含池和验证映射，但不等于全部宿主成本。预准备缓存可能计在组外，不能把组内
下降直接解释为整机净节约。CPU 秒是名义 60 秒空闲窗口的累计组用量，不是
墙钟延迟或纯扫描算法成本；启动、读回、写入和写后 CPU 分别记录。
完整读回耗时含四 VM 的读取、逐字节/摘要校验及控制协议，不是单次 load 延迟。
扫描可在顺序启动期间发生，all-ready 不代表同步扫描起点。

本批没有旧/新版 A/B、KSM、Firecracker、Docker、压缩、共享库/DAX、
daemon 故障注入或 macOS 对照。N=1 不提供置信区间、尾延迟、长期可靠性或
2–3K VM 密度结论，不与之前受干扰或不同固件的批次合并。

## 实验数据和分析

### 空闲占用、CPU 与读回

以下均为四 VM 整组，N=1；内存为就绪后 60 秒快照，CPU 为该空闲窗口的累计值。

| 内容 | 模式 | 计费 MiB | PSS MiB | 组 CPU 秒 | 完整读回 ms |
|---|---|---:|---:|---:|---:|
| 重复内容 | off | 469.97 | 480.33 | 0.365 | 722.42 |
| 重复内容 | physical | 212.14 | 214.45 | 7.070 | 873.07 |
| 相同随机内容 | off | 470.16 | 480.32 | 0.363 | 710.79 |
| 相同随机内容 | physical | 292.25 | 294.89 | 7.412 | 1003.66 |
| 实例独有随机内容 | off | 469.93 | 480.26 | 0.361 | 673.10 |
| 实例独有随机内容 | physical | 457.06 | 472.43 | 3.553 | 873.76 |

重复内容和相同随机内容的计费差值分别为 -257.83 / -177.91 MiB；
额外空闲 CPU 分别为 6.706 / 7.048 秒。独有随机内容仅差 -12.87 MiB，
仍额外消耗 3.191 CPU 秒。差值只是本批观测水平，不是重复测量的效应估计。
独有业务数据不排除 guest 中其他公共页面，因此少量下降不能归为该随机堆的共享。

physical 从各自 all-ready 占用起持续减少 128 MiB、并保持到窗口结束的采样区间：
重复内容为 0.774–0.824 秒，相同随机内容为 1.092–1.180 秒；
独有随机内容及三个 off 条件均未达到目标。这不是首次合并或完整收敛时间。

读回后，重复内容 physical 的计费占用为 212.60 MiB，相同随机内容为
292.70 MiB，均接近读回前。这支持本次共享在读取后保留；与此同时，
完整读回比相同内容的 off 多约 151 / 293 ms。当前矩阵不能把额外耗时
拆成 hash、IPC、映射或 guest 执行的独立贡献。

### 全量私有写后的代价

四 VM 均将数据完整改写为实例独有内容，再观察 30 秒；N=1，整组 MiB。

| 原始内容 | off 计费 | physical 计费 | off PSS | physical PSS |
|---|---:|---:|---:|---:|
| 重复内容 | 471.01 | 486.03 | 481.13 | 477.33 |
| 相同随机内容 | 471.17 | 499.59 | 481.11 | 491.68 |
| 实例独有随机内容 | 470.98 | 464.71 | 481.06 | 479.32 |

相同随机内容改写后，physical 比 off 多计费 28.42 MiB。该快照中，
kernel 项为 30.82 / 5.54 MiB，slab 为 25.89 / 1.69 MiB
（均为 physical / off；**slab 属于 kernel 子项，不能再次相加**）。

与此同时，physical 池 memfd 的已分配文件块从空闲末的 72.80 MiB
降至写后 30 秒的 8.80 MiB，逻辑文件大小仍为 128 MiB。这是文件存储诊断，
不是净内存指标；它说明不能把写后额外计费全部解释为旧 payload 未释放。
四 VM 仍有 70,801 个私有 pool VMA，接近写前的 70,800 个。
这些观察提示下一步优先检查映射及元数据的持续成本；尚未隔离出确切因果贡献，
也未据单个窗口判断长期内存泄漏。

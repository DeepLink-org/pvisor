# macOS 四实例物理页共享验收

已实现两条路径：共同启动内核的私有 COW 基底，以及运行期间按完整宿主页内容合并的 daemon 物理池。四个独立 Linux VM 的真实验收通过，每个配置 **512 MiB、1 vCPU**，各持有 **64 MiB 确定性随机应用数据**。

开启运行期共享：

```sh
pvisor-daemon serve --memory-pool --memory-pool-mode physical-pages --state /tmp/pvisor-physical
# 使用 readiness 输出的规范 socket 路径：
pvisor run -d -m 512m --cpus 1 --memory-pool /private/tmp/pvisor-physical/memory-pool/pool.sock alpine sleep 3600
```

`--shared-kernel-base DIR` 可以独立开启共同启动基底。与运行期物理池组合时，基底区域由自身 COW 管理，扫描器只接管普通 RAM。默认 daemon 模式仍为冷压缩，需显式选择 `physical-pages`；旧 macOS `physical` 配置保留原有压缩含义，不能原地替换正在使用的配置。

## 实现与正确性

物理池复用 Linux 路径的内容索引、完整字节比较、跨连接重复候选、只读描述符和槽位引用。macOS 使用私有、未链接的文件，按 16 KiB 宿主页存储；没有 Linux memfd 的大小封印，固定大小和已引用槽位不可变是可信 owner 的责任。daemon 在发放引用之前注册 kqueue 进程退出事件，连接断开不允许重用仍可能被映射的槽位。

VM 只采样驻留页。采样、最终字节复核和映射替换都停驻 CPU、排空设备引用；发布、哈希、引用释放和原 backing 打洞在该屏障外执行。映射使用 `MAP_PRIVATE`，读取保留共享，CPU 和设备写入 COW。已写入页在释放旧引用前重新映射为匿名私有页，消除对旧文件槽位的 shadow 关系。转换失败终止 runner。快照、整 VM offload 和同一 VM 的冷压缩 pager 与此模式互斥。

原生 HVF 小测试验证运行后重新映射、共享页指令读取、CPU 写入、设备式宿主写入、源文件不变，以及旧槽位改写后私有内容仍正确。四实例测试逐字节验证读回、单实例 25% 写入、全部实例各自 100% 写入，随后移除一台并再次验证其余三台全部 64 MiB 内容。

## 同机静态读数

2026-10-24，Apple Silicon、24 GiB 宿主内存、macOS 27.0.1。使用同一个签名 debug `pvisor`，每个条件一个新四实例组，约启动后 25 秒查询 RAM。两组均无观测到的 RAM paged-out 页。原始记录、输入二进制、源码清单及失败诊断保存在本目录忽略的 [`.data/macos-four-512-20261024/`](.data/macos-four-512-20261024/)。复现入口见 [daemon README](../README.md#validation)。最终二进制与固件已冻结保存，避免其他测试重新构建开发二进制时覆盖 Hypervisor 签名。

| 观测量（MiB，单组静态读数） | 关闭共享 | 运行期物理池 |
|---|---:|---:|
| 四 VM RAM 的驻留页引用之和 | 364.81 | 366.09 |
| 四 VM RAM 的不同驻留 backing | 364.81 | 259.09 |
| 跨 VM 重复驻留引用被复用 | 0 | 99.17 |
| 同一 backing 同时出现在四 VM 的范围 | 0 | 8.19 |
| 物理池初始 payload | 0 | 73.02 |
| 全量私有写入并等待后，物理池 payload | 0 | 17.13 |

四 VM 的不同驻留 RAM backing 读数相差约 **106 MiB**，其中约 **99.2 MiB** 是跨实例重复引用；另有同一实例内多个地址复用同一页，所以两项不相等。物理池 payload 与 VM 共享映射重合，不能直接相加。完整私有写入后，各 VM 的 pinned 引用降到约 17.9–19.2 MiB；pool payload 降到约 17.1 MiB，原应用共享槽位得到回收。所有完整性和退出隔离检查通过。

这些数值证明指定窗口中的共同驻留 backing 和安全 COW，**不是整机净节省量**。不包含完整进程元数据、未映射文件缓存、内核与管理进程成本；Mach 对象/偏移身份也不是 PFN。`vmmap` 的进程 footprint 原文保留作辅助：关闭组约每台 111.4–111.5 MiB，共享组约 16.7–17.0 MiB，但文件 backing 的计费方式改变，不能把这项差额称作物理节省。没有随机重复轮次、置信区间、CPU/延迟、启动/写入峰值或生产密度结论。

## 实际限制与保留的失败

当前 guest 内核使用 4 KiB 页，宿主页是 16 KiB。相同虚拟堆数据在不同 VM 中的物理排列可能不同；只有完整相等的 16 KiB 块可以合并。这组独有随机页不能全部在四台之间共同合并，初始各 VM 的 pinned 量也明显不同。不能从“应用内容相同”推导 64 MiB 全部共享，更不能把配置的总共 2 GiB 当作节约分母。

早期验收对每台共享超过 48 MiB 的假设未成立，原始 RAM 记录保留。一个先前的关闭组包含大量宿主 paged-out 页，虽通过完整性检查，仍不与最终驻留组混合。另一次报告读取了尚未写完的诊断 JSON 而失败；诊断输出随后改为原子发布。上述早期记录均未计入上表，最终两组完成所有校验。

池预算之外仍有索引、扫描缓冲与每页状态成本。该模式依赖支持 mmap 和打洞的临时文件系统，可能产生磁盘 I/O；它不压缩，不自动重新连接，pool 丢失会终止依赖它的 VM。Linux 交叉编译因本机缺少 `x86_64-linux-musl-gcc` 未完成；本报告仅验证 Apple Silicon。

验证：552 项相关回归通过；原生 HVF 基底与运行期重映射测试、旧冷压缩组合验收、Clippy 和相关库 rustdoc 均通过。
